[[installation]]
=== Installation

The plugin needs Grails 8, a GORM data source (it stores its login tokens with GORM and the passkeys with Spring's
`JdbcTemplate` on the same data source) and `grails.serverURL`.

[source,groovy,subs="attributes"]
----
dependencies {
    implementation 'io.github.gpc:grails-passwordless-login:{version}'

    // The plugin compiles against these but does not bring them in: the application decides the versions.
    implementation 'org.springframework.boot:spring-boot-starter-security'
    implementation 'org.springframework.security:spring-security-webauthn'
}
----

Do not add `grails-spring-security-core` next to it; see <<springSecurity>>.

[[serverUrl]]
==== grails.serverURL

Login links are built from `grails.serverURL`, never from the `Host` header of the request, which the requester
controls. The links are also built on a background thread that has no request. The application refuses to start
without it:

[source,yaml]
----
grails:
  serverURL: https://example.com
----

The same value gives the passkey relying party its id (the host) and its allowed origin; see <<passkeys>>.

[[schema]]
==== Schema

The plugin creates no tables on its own. An application that keeps its schema in Liquibase
(`grails-database-migration`) includes the plugin's changelog from its own:

[source,groovy]
----
databaseChangeLog = {
    include file: 'passwordless-login/changelog.groovy'
}
----

It creates three tables:

[cols="1,3"]
|===
| `login_token` | The plugin's own. Holds the SHA-256 hash of each link's token, never the token itself, when it expires and when it was used.
| `user_entities` | Spring Security's WebAuthn table for a passkey user, with a unique sign-in name (the email).
| `user_credentials` | Spring Security's WebAuthn table for the passkeys themselves.
|===

The changelog is written for PostgreSQL. An application that does not use Liquibase must create the same tables
itself, from that file.
